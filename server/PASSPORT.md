## 3. Три перші команди, якщо щось сталось

```bash
ssh -i ~/.ssh/unitex_droplet root@134.209.94.12   # 1. зайти на сервер
systemctl --failed && docker ps && df -h /        # 2. подивитись, що впало
tail -5 /root/backup_log.tsv                      # 3. чи є свіжа копія
```

Якщо SSH не працює — **консоль DigitalOcean у браузері**, ключа не потребує:
дроплет → Access → Reset Root Password → Launch Droplet Console.

## 4. Що робити найчастіше

```bash
# фасад ЕРП зламався після викладення — відкотити
bash /root/Iryna_Karmazina/server/rollback_ui.sh        # показати версії
bash /root/Iryna_Karmazina/server/rollback_ui.sh 1      # на крок назад

# зробити резервну копію просто зараз
systemctl start unitex-backup.service

# клієнту потрібен новий пароль до кабінету
cd /root/Iryna_Karmazina/server && python3 cabinet_admin.py passwd --email пошта@клієнта

# перезапустити службу
systemctl restart unitex-gateway     # прошарок прав
systemctl restart unitex-cabinet     # кабінет клієнта
systemctl restart mybot              # телеграм-бот
```

## 5. Що не можна робити ніколи

- ❌ копіювати `www/index.html` на сервер руками — тільки `server/deploy_ui.sh`
- ❌ видаляти будь-що «зайве»: файли, гілки, воркфлоу n8n, рядки в базі
- ❌ `git push --force`, «лагодити» розбіжність гілок злиттям
- ❌ міняти `noco.db` на місці, не зупинивши контейнер і не зробивши копію

---

## 6. Єдина необоротна поломка

**Втрата пароля від резервних копій.** Він у менеджері «Паролі» (запис
«Юнітекс резервні копії») і в `/root/.backup-pass` на сервері. Друга копія
марна саме в тому випадку, від якого захищаємось — коли сервера більше немає.

📌 **Дія: покласти пароль у третє місце — поза сервером і поза Mac.**
